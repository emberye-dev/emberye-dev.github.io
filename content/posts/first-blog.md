## 为什么开始写博客

大三这个节点，我第一次认真地把"会用 AI"和"会做系统"区分开来。

过去一段时间我接触了大模型 API、Agent、RAG，也确实用 AI 帮我完成了不少东西：写脚本、搭小工具、做游戏逆向与复刻。用起来很顺，于是一种错觉很容易产生——好像自己已经具备开发能力了。

但随着做得越多，越发现一个事实：工具用得熟练，不等于我能独立设计、调试和维护一个系统。当需求变复杂、出错的地方不再是我熟悉的那几步时，AI 帮不了我判断"为什么错"。

所以我想开始写博客。它不是给别人看的展示墙，首先是给我自己的记录：我做过什么、怎么解决的、学到了什么、能力是怎么一点点变化的。把这些公开出来，也能逼着自己把过程讲清楚——讲不清楚，往往说明我其实没弄明白。

## 我的当前状态

诚实地说，我现在的起点并不高：

- **编程基础**：学过 Java、C++、C#，但主要停留在语法层面，缺少项目实践，部分内容已经遗忘。
- **独立开发**：目前做中小型项目还是较依赖 AI 辅助，还做不到从零独立交付。
- **数据结构与算法**：学得不扎实，需要重新建立基础。
- **计算机基础**：操作系统、网络、数据库、计算机组成都接触过，但理解较浅，还没有形成一个体系。
- **AI 实践**：已经尝试过大模型 API、Agent、RAG，现在正在用 AI 做游戏逆向与复刻的小项目。
- **兴趣方向**：最不愿放弃的是 AI，希望把它用在学习和开发上，真正改善自己的效率。

## 未来的学习方向

我给自己定的定位是 **AI 增强型技术创造者**：理解计算机技术、善用 AI、能完成真实项目，并且能持续解释和展示自己的工作。

想逐步积累的能力组合是：**AI 应用能力 + 软件工程能力 + 数字媒体应用经验**。

围绕这个定位，我准备走四条相互支撑的主线：

1. **AI 应用能力**——从"调用工具"走向"设计应用"。先打好大模型 API 调用、提示词设计、Agent 架构、RAG 流程、Function Calling 和工作流自动化的基础，再做后端接口与部署。
2. **软件工程能力**——补上"把需求做成能运行、能交付、能维护的项目"这一课，完整走一遍 需求 → 设计 → 数据库 → 后端 → 接口 → 部署 → 维护。
3. **计算机基础**——每天留一段固定时间学数据结构与算法、计算机网络、操作系统、数据库，并用项目里的真实问题去验证理解，而不是等"全部学完"再动手。
4. **博客与个人展示**——用这个博客沉淀前三条主线产生的真实经验，形成公开的能力记录。

## 当下的具体行动

- 已经搭建了这个博客站点（Hugo + PaperMod，内容用 Markdown 写作）。
- 接下来会整理 GitHub 账号、项目仓库和学习笔记的结构。
- 学习上，优先推进一个主项目，其余活动围绕它展开；每天用几分钟记录素材，每周从中提炼一篇。

我不打算把还没做的事写成已经完成的成果。这篇文章更像是一个起点标签——往后每一篇，我希望都能回答一个具体的问题，并且有真实的过程或结果做支撑。

如果一年后回头看，我希望能确认的只有一件事：能力确实变了，而不只是多了一堆记录。
